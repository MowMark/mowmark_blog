# 写作风格指南 (Writing Style Guide)

## 语调

- **口语化第一人称** — 像懂行的朋友在聊天，用"我""我的方案""我个人"
- **务实不卖弄** — 不强行输出"最佳实践"，承认取舍（"选哪个看个人口味"）
- **拥抱折腾** — 面向同样喜欢自己动手的读者

## 标点

**半角标点**（`，` → `,`, `。` → `.`, `：` → `:`, `；` → `;`, `？` → `?`, `！` → `!`）

英文术语和中文之间**不加空格**：
- ✓ `Ubuntu下开发`、`SOCKS5协议`
- ✗ `Ubuntu 下开发`、`SOCKS5 协议`

## 技术术语

- 英文术语用反引号包裹：`SMB`、`DDC/CI`、`BEP`
- `**加粗**` 标重点
- `>` blockquote 做补充说明 / 避坑提示
- 代码块前带一句文字说明用途

## 结构

- **开篇交代动机** — 为什么写、遇到什么需求
- **理论 → 实践** — 原理一两段讲够用，然后上操作步骤
- H2 大块 → H3 细化，`---` 做视觉分隔
- **表格做对比**（框架对比、协议对比、配置对比）
- **末尾小结** — 一句话概括核心逻辑
- **`{{< ref >}}`** 建立文章间相互引用，形成系列

## 示例片段

```markdown
## 为什么要用 X

日常遇到 Y 问题, 常见的做法是 A 或 B. 但这两者各有不足...

X 的优势在于:
- **去中心化**: 不经过任何第三方.
- **增量同步**: 只传输变化部分.

1. **下载**: 前往官网下载安装包.

2. **配置**: 按以下步骤:
```

## 不要写

- 不要写 `categories`（系统从目录路径自动生成）
- 不要写 `lastmod`（靠 `enableGitInfo` 从 git 获取）
- 不要用"首先/其次/最后"式刻板过渡
- 不要写全角标点
